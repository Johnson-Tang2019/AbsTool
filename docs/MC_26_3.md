# Minecraft 26.3 development and release

Minecraft 26.2 remains the repository-root Gradle project. Its source lives in
`common/`, `26.2Fabric/`, and `26.2NeoForge/`; its version stays in the root
`gradle.properties`. Its original `v<version>` release tags and workflow remain
the 26.2 release path.

Minecraft 26.3 is an independent Gradle project under `26.3/`, with its own
`common/`, loader modules, `gradle.properties`, wrapper, and dependency graph.
Changes for one Minecraft version must be made in that version's source tree.
The 26.3 client stores its settings as `abstool-26.3.json` and its vault data
as `abstool-26.3-vaults.json`; the 26.2 files retain their original names.

Build from the repository root:

```text
./gradlew assemble                           # Minecraft 26.2
./26.3/gradlew -p 26.3 assemble              # Minecraft 26.3
```

The 26.3 project uses Java 25, Gradle 9.6.0, Fabric Loader 0.19.5, Fabric API
0.160.6+26.3, Cloth Config 26.3.158, and NeoForge 26.3.0.23-beta. Its releases are prereleases
because the NeoForge 26.3 toolchain is still in beta. Fabric optional schematic
rendering requires Minecraft 26.3, the Iris 26.3 public and rendering interfaces,
and audited Litematica/MaLiLib bytecode. Future Iris releases that preserve the
required interfaces can work without a version-list edit; incompatible interfaces
disable the integration. Xaero waypoint integration similarly checks its required
API and data model at runtime instead of matching a single version string.

Both loaders use the shared Xaero integration under
`26.3/common/src/main/java/com/abyssredemption/abstool/client/compat/xaero/`.
Platform adapters supply mod discovery and screen events. `verifyXaeroParity`
checks that both JARs package the same shared bytecode and their own mixin plugin;
the root `build` and 26.3 release workflow run that check.

Release tags use `v<mod_version>-mc26.3`, for example
`v0.5.0-beta.6-mc26.3`. That tag runs only
`.github/workflows/release-26.3.yml`, publishing both loader JARs. A plain
`v<mod_version>` tag continues to select the 26.2 release workflow. Build CI
checks both independent Gradle projects.
